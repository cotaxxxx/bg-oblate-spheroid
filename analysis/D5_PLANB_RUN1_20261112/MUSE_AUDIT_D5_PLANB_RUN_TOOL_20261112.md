## 2. 被覆の検査 `cover`（依頼項目1・最重要）

コードを精読し、chat の試験 `t_planb_cover.py`（7件）・`t_planb_run.py`（15件）を自分の環境で再実行して全件 PASS を確認したうえで、独自の負例9件を追加した（親 j=0 の全格子を実在の格子で構成し、`--parents 0` で検査）。

- 最終記録の選択：名前＋`_h0`／`_h1` のいずれかが存在する記録は最終記録から外れる。片方の子だけが存在する場合は親も子も最終集合の被覆を完成できず、d の敷き詰め検査で FAIL になる（独自試験C）。
- 入れ子の子：孫（level 2）による敷き詰めも正しく扱われる（独自試験Eで PASS、試験Dの「親＋両子」でも親が正しく除外される）。
- 敷き詰め検査：各（親帯 Dj、τ セル、λ セル）群について、d 区間をソートし、始点＝Dj、終端＝2Dj、隣接区間の端点一致を厳密な分数で検査する。重なり（別名の重複区間、独自試験G）も隙間も FAIL になる。
- 全セルの存在：期待格子（12親帯 × τ32 × λ26、部分検査時は `--parents` の範囲）との集合一致を検査する。欠けたセルは FAIL（chat 試験F）。
- 各最終記録に `check_box` を適用し、λ ∈ [2/5, 33/50]、方式 ID `PLANB-CUT`、H_B⁻ ＞ 0（厳密な分数、0 は FAIL：chat 試験D・独自試験F）を検査する。Dj が親帯でない記録は除外され FAIL（独自試験H）。
- 重複した名前：辞書で後の行が勝つ。後の行が負値なら FAIL（独自試験I）。名前の重複で被覆の穴が隠れることはない（穴は格子集合の不一致として現れる）。

以上より、`cover` が PASS を返すのは、最終記録が領域 r ∈ [15/16, 1 − 2⁻¹⁶] × τ ∈ [0, 1] × λ ∈ [2/5, 33/50] を隙間も重なりもなく覆い、全記録が上記の検査を通るときに限る、という依頼項目1の主張を確認した。

## 6. 仕様の確認（依頼項目5）と軽微な観察

仕様側の確認：

- 境界 d ＝ 1/16 は V4 の親帯 j ＝ 0 の下端と一致し、隙間はない。境界 d ＝ 2⁻¹⁶ は薄いカラー（r ∈ [59999/60000, 1]、すなわち d ≤ 1/60000）と **[2⁻¹⁶, 1/60000] の範囲で重なる**（1/60000 ＞ 2⁻¹⁶）。重なりは被覆の重複ではなく両側が独立に正値性を担う範囲で、隙間にはならない。
- cut の支払い L_cut ＝ 552960/16777217 は監査済み `box_lower` の中で外箱ごとに1回差し引かれ、R1B の子もそれぞれ1回ずつ支払う（各子は独立した部分箱として下界を持つ。較正の j11 半分箱の値とも整合）。
- 証明書の項目（仕様 §5-5）：全記録（gz）、COVER PASS の出力、抜き取りの記録、producer との比較表、ソースの SHA、最小の H_B⁻ とその外箱、SHA256SUMS——抜けは見つからなかった。

軽微な観察（いずれも健全性に影響しない）：

1. `cover` は記録に保存された H_B⁻ の文字列を信頼する（V4 の道具と同じ設計）。偽値・誤計算への対抗は、仕様が別途定める chat の 200 箱抜き取り（文字列一致）と producer 比較が担う。本走の証明書では、この2つが揃うことを採用の前提として確認されたい。
2. 再開時の途中行の除去は、末尾の改行がない**完全な**最終行も落として再計算する。安全側の挙動で、損失は最大1箱の再計算にとどまる。
3. `cover` は記録の `spec` 欄と箱の `j` 欄と Dj の一致を検査しない。被覆は Dj による群分けと `check_box` で強制されるため、表示上の事項にとどまる。
